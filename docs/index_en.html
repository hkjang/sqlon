Engineered for Enterprise DBA & SRE Workflows

SQLON bridges LLM intelligence with rigid database security, deterministic schema compilation, and operational change control.

MCP Native Ecosystem

104+ tools, resources, and prompt templates exposed via stdio & HTTP transports. Plugs directly into Claude Desktop, Cursor IDE, VS Code, and custom AI agents.

Zero Schema Hallucination

Compiles dataset JSON metadata into in-memory catalog graphs. Evaluates join paths, candidate column matches, and candidate ambiguity before any query is written.

Fail-Closed Guardrails

Enforces 33 AST-level SQL validation rules, forced read-only transaction locks (`tx_read_only=1`), query cost evaluation (`EXPLAIN`), and PII data masking.

Multi-DBMS Native Drivers

Pure-Go execution engine for PostgreSQL, MySQL, and MariaDB without CGO. Specialized OCI driver module (`sqlon-oracle`) for enterprise Oracle databases.

Approval-Gated Change Control

Provides SREs with governed DDL/DML change request workflows, dry-run reviews, sign-off execution, and audit logging to satisfy compliance standards.

Fleet Observability & SRE

Deep cluster inspection, active session diagnostics, deadlocks detection, index recommendation advisor, and OpenMetadata lineage synchronization.

The Evidence-Driven NL2SQL Pipeline

How SQLON guarantees safe, accurate SQL generation from user questions.

STAGE 1

Context Compilation

Scans dataset schema graphs, resolves candidate table joins, and verifies filter parameters against catalog metadata.

STAGE 2

Clarification Check

If columns or filters are ambiguous, halts execution and presents specific questions back to the human operator.

STAGE 3

Skeleton Filling

Generates target SQL dialect strictly within pre-validated slot skeletons — eliminating invented table names.

STAGE 4

AST Guardrail Check

Validates SQL syntax against 33 security rules (rejecting unauthorized DDL/DML, cross-schema leaks, unsafe joins).

STAGE 5

Sandbox Execution

Executes query under explicit read-only transaction locks and streams clean JSON data with audit tracking.

Supported Target Databases

Pure-Go drivers, zero CGO, zero external binary dependencies.

PostgreSQL

Pure Go
  • Driver: `pgx/v5`
  • Lock: `default_transaction_read_only=on`
  • Dialect: PostgreSQL (v12-v16)
  • Full DSN & Connection String support

MySQL 8.x

Pure Go
  • Driver: `go-sql-driver/mysql`
  • Lock: `transaction_read_only=1`
  • Dialect: MySQL 8.x
  • Pure Go connection pooling

MariaDB 10.x / 11.x

Pure Go
  • Driver: `go-sql-driver/mysql`
  • Lock: `tx_read_only=1`
  • Dialect: MariaDB
  • Zero CGO compilation

Oracle DB

OCI Plugin
  • Driver: `godror` / OCI SDK
  • Runtime: `sqlon-oracle` build
  • Dialect: Oracle 19c / 21c
  • Enterprise capability contracts

Frequently Asked Questions

Direct answers for SRE teams, DBAs, and Answer Engine AI crawlers.

SQLON is an evidence-driven AI database operations platform built for Database Administrators (DBAs), Site Reliability Engineers (SREs), and Enterprise AI application developers. It transforms natural language instructions into validated, secure SQL queries while providing fleet observation, performance profiling, and governed change control workflows.
SQLON loads JSON dataset metadata into memory and compiles an explicit catalog, join-graph, and candidate column index. Before generating SQL, the `prepare_sql_context` engine creates a rigid SQL skeleton with pre-validated table joins. If a query contains ambiguous terms, SQLON enters a mandatory clarification state to prompt the user rather than guessing schema elements.
Model Context Protocol (MCP) is an open standard introduced by Anthropic that allows AI models to safely interact with external tools and datasets. SQLON implements standard MCP over both stdio (for local subprocesses) and HTTP (for microservices/gateways), providing 104+ tools, resources, and prompts for Claude Desktop, Cursor IDE, VS Code, and custom AI agents.
Yes. SQLON strictly enforces fail-closed guardrails. Read-only queries run under explicit engine transaction locks (`default_transaction_read_only=on` for Postgres, `transaction_read_only=1` for MySQL). State-modifying operations (DDL/DML) are protected by multi-step approval workflows, AST security validation against 33 rules, and audit logging.
SQLON standard binary supports PostgreSQL (v12-v16), MySQL (v8.x), and MariaDB (v10.x/v11.x) using pure-Go drivers with zero CGO dependencies. Oracle DB is supported through the specialized `sqlon-oracle` build which includes Oracle Call Interface (OCI) bindings.
