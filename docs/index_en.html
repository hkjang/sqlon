What SQLON does

One operational layer between AI and your databases.

The system exposes the evidence and controls an agent needs without asking the model to invent schema details or bypass established operational checks.

CTX

Metadata-grounded context

Compile datasets into an in-memory catalog, candidate index, join graph, metric registry, and dialect-aware prompt context.

ASK

Explicit clarification

When a table, column, metric, or filter is ambiguous, return a structured question instead of silently choosing an interpretation.

SQL

Guarded SQL execution

Validate SQL, inspect its execution plan, enforce engine-level read-only settings, and bound the returned result.

MCP

MCP-native interfaces

Connect local clients over stdio or expose Streamable HTTP for gateways and service deployments. REST and admin interfaces are included.

SRE

Operations & diagnosis

Inspect connections, sessions, locks, query behavior, and database health through a consistent operations-oriented tool surface.

APR

Governed changes

Keep state-changing work separate from read-only analysis with review, dry-run, approval, and audit-oriented workflows.

Evidence-driven workflow

A visible path from intent to execution.

Each stage produces something the operator or calling agent can inspect before moving forward.

Resolve context

Search the catalog for relevant tables, columns, metrics, filters, and verified relationships.

Clarify ambiguity

Stop and ask focused questions when the available evidence does not support one clear interpretation.

Build SQL

Fill a dialect-aware skeleton while keeping identifiers and joins tied to compiled metadata.

Validate & explain

Apply static policy checks and inspect the database execution plan before running the query.

Execute safely

Run in a read-only transaction and return a bounded result with traceable operational context.

FAQ

The short version.

Practical answers for teams deciding where SQLON fits.

Does SQLON generate SQL entirely on its own?

SQLON prepares grounded context, join paths, a SQL skeleton, and validation tools for an AI client or application. The recommended flow keeps each decision inspectable and asks for clarification when the metadata is ambiguous.

Can it run directly against production databases?

SQLON includes read-only transaction settings, SQL policy validation, plan inspection, and bounded execution. Those controls reduce risk, but your team still owns database credentials, network access, role design, policy configuration, and rollout testing.

Which database engines require CGO?

The standard PostgreSQL, MySQL, and MariaDB build uses pure-Go drivers. Oracle support is packaged separately because the godror runtime depends on Oracle OCI.

How do AI clients connect?

Use stdio when a desktop client launches SQLON locally, or Streamable HTTP at /mcp when SQLON runs as a service. REST APIs and a web administration interface are available in HTTP mode.
